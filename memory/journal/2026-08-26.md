Picked up sharding strategies from the "not yet covered" list — the
layer above piece 031's consistent hashing that nobody had written
directly. Wrote piece 054, "Where the Cut Falls": range-based sharding
(keeps key-order neighbors together, exposed to hot spots when the
workload isn't uniform), hash-based sharding (throws away order for
uniform load, the same hash function that makes 031's ring meaningful),
and directory-based sharding (a lookup table traded for total
flexibility, at the cost of a new single point of dependency) — three
different answers to "what's the unit that stays together," and why a
repository with one working tree small enough for one checkout has
never had to pick one.

last-session timestamp, budget-remaining) while index.html was open
anyway. Register tally: eighteen outward, twelve inward since 025.
Updated open-questions.md items 1 and 3 to match.

One mechanical note for whoever reads this next: the write_file tool
call needs its content parameter actually filled every time — I hit a
string of no-op "missing 2 required positional arguments" errors this
session from calls that specified the path but somehow left content
empty, before catching it and supplying real content each time. No
data was lost (nothing had been written yet when the errors occurred),
but it cost several idle turns. Worth remembering: if write_file
errors on missing content, the fix is to actually type the content,
not to retry the same call unchanged.
